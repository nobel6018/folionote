# 경쟁 서비스 기능 조사 (2026-08-11)

레퍼런스 서비스 외에 Notion을 웹사이트로 발행하는 서비스 7종의 공개 기능/가격 페이지를 조사해,
folionote에 없는 기능을 추렸습니다. 레퍼런스 서비스 자체와의 대조는 `docs/feature-parity.md`에
있고, 이 문서는 그 밖의 서비스를 레퍼런스로 삼습니다.

## 우선순위 제안

### 1순위: 커스텀 코드 주입

5개 서비스가 제공하고, Super와 Sotion은 유료 플랜의 대표 기능으로 내세웁니다.
사용자가 우리 코드를 고치지 않고 분석 스크립트, 폰트, 색 보정, 위젯을 붙일 수 있게 하는
탈출구라서, 나머지 미구현 기능의 상당수를 사용자가 스스로 우회하게 해줍니다.

구현은 가볍습니다. `site.config.ts`에 `customCode: { head, bodyEnd, css }`를 받아
`_document.tsx`와 `_app.tsx`에서 주입하면 됩니다. 주의할 점은 CSS 주입 순서입니다.
`styles/folio-overrides.css`가 react-notion-x를 이기려고 `:root:root`, 클래스 중복
(`.container.container`) 같은 특이도 기법을 쓰고 있어서, 사용자 CSS가 이를 이기려면
가장 마지막에 들어가야 합니다.

### 2순위: Notion 장애 시 캐시 폴백

HelpKit만 명시적으로 내세우지만(“Content caching for reliability”), 우리에게는
채택률과 무관하게 값이 큽니다. 실제로 Notion이 User-Agent 없는 요청을 403으로 막아
전체 사이트가 500을 내는 장애를 겪었습니다. 현재는 `getStaticProps`가 실패하면
ISR 재생성이 실패하고 그대로 에러 페이지가 나갑니다.

`getPage()`가 실패했을 때 마지막으로 성공한 recordMap을 반환하도록 하면 됩니다.
Redis를 켠 환경이면 저장소는 이미 있습니다(`isRedisEnabled`). Notion이 죽어도
사이트는 어제 내용으로 계속 서비스됩니다.

### 3순위: 페이지별 SEO 메타 덮어쓰기

4개 서비스가 제공하고, Super는 유료 플랜 기능으로 둡니다. 지금은 `PageHead`가
Notion 페이지의 `Description`, `Social Image` 속성을 읽습니다. 데이터베이스에 속한
글은 동작하지만, 일반 페이지는 속성을 붙일 수 없어 사이트 기본값으로 폴백합니다.
`site.config.ts`에서 pageId별로 title/description/ogImage/noindex를 덮어쓰는 맵을
받는 편이 확실합니다. `pageUrlOverrides`와 같은 형태라 사용자에게 익숙합니다.

### 4순위: 리다이렉트와 페이지 숨기기

Super Pro의 기능입니다. 우리는 사이트맵과 브레드크럼에 모든 페이지를 넣습니다.
Notion 트리에 작업용 페이지를 두면 그대로 노출되고 검색엔진에도 올라갑니다.
`hiddenPages` 배열로 사이트맵/검색/크럼에서 빼고 `noindex`를 주는 정도면 충분합니다.
리다이렉트는 `next.config.js`의 `redirects()`에 config 값을 넘기면 됩니다.

### 5순위: 태그, 관련 글

Feather가 블로그 특화로 내세우는 조합입니다. 우리 타깃(레퍼런스 사이트)이 블로그이고,
Notion 데이터베이스에 이미 multi_select 속성이 있으면 데이터는 갖춰진 셈입니다.
글 하단에 같은 태그를 가진 글을 뽑아 붙이는 수준이면 `getSiteMap()` 결과만으로 됩니다.

### 보류: 접근 제어와 멤버십

채택률 1위(6/7)이고 대부분 유료 플랜의 핵심입니다. 그런데 우리 아키텍처와 정면으로
충돌합니다. 지금은 순수 SSG + ISR(`revalidate: 600`)로, 모든 응답이 방문자와 무관하게
캐시됩니다. 비밀번호나 멤버십은 방문자별 판정이 필요해서 middleware + 쿠키가 들어가야
하고, 보호 대상 페이지는 CDN 캐시에서 빠져야 합니다. 정적 사이트의 속도 이점을
그 페이지에서는 포기하는 선택입니다.

부분 도입은 가능합니다. 사이트 전체 비밀번호(Wraptas의 “サイトパスワード” 방식)는
middleware 한 개와 쿠키 하나로 끝나고 보호 범위가 전부이므로 캐시 정책이 단순합니다.
페이지 단위 접근 제어나 Stripe 결제 멤버십은 사실상 별개 제품이라, 하려면 별도 논의가
필요합니다.

### 보류: 다국어

Super Pro와 HelpKit이 제공합니다. Notion 쪽에 언어별 페이지 트리를 어떻게 두는지부터
정해야 하고(별도 데이터베이스 / 속성 / 페이지 쌍), `hreflang`과 라우팅이 함께 갑니다.
`_document.tsx`의 `lang`은 이미 config를 따르므로 단일 언어는 맞춰져 있습니다.

### 보류: AI 검색, 분석 대시보드

HelpKit의 AI 챗봇/시맨틱 검색, Super와 Bullet의 분석 대시보드는 둘 다 별도
백엔드와 지속 비용이 드는 기능입니다. 분석은 사용자가 커스텀 코드 주입으로 Plausible이나
GA를 붙이면 되므로, 1순위를 하면 상당 부분 해소됩니다.

## 참고: 우리가 이미 앞서는 부분

- 디자인 실시간 미리보기 어드민(`pages/admin.tsx`)은 Wraptas만 내세웁니다
- 폰트를 언어별(Ko/En/Ja)로 나눠 지정하는 것은 레퍼런스 서비스 외에는 보이지 않습니다
- 팝업, CTA 버튼, 하단 네비게이터, 스크롤 프로그레스 바는 레퍼런스 서비스 PRO 급 기능입니다
- 셀프 호스팅이라 페이지 수, 방문자 수, 사이트 수 제한이 없습니다
